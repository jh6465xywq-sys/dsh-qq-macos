# 01 · 为什么在 Mac 上这么难

这一篇不是教程，是**帮你省时间**的。我在这两条死路上花了大半天，你可以直接跳过。

---

## 路一：NapCat macOS 安装器

NapCat 是 QQ 协议端里最成熟的，官方给了一个 macOS 安装器（`NapNeko/NapCat-Mac-Installer`），界面友好，装完显示：

```
QQ 版本        ✅ 7.0.2-53644
NapCat 版本    ✅ 4.18.41，已是最新
程序入口       ✅ NapCat
```

**看起来全绿了。** 但启动 QQ 之后，NapCat 的 WebUI（6099）根本不存在，`napcat` 目录里没有日志、没有 `onebot11_<uin>.json`，6199 端口只有 LISTEN 没有 ESTABLISHED。

### 它到底要做什么

NapCat 在 Mac 上的注入方式是**改 QQ 的启动入口**：

1. 把 `/Applications/QQ.app/Contents/Resources/app/package.json` 的 `main` 从 `./application.asar/app_launcher/index.js` 改成 `./loadNapCat.js`
2. `loadNapCat.js` 里判断 `process.argv.includes('--no-sandbox')`，真就加载 NapCat，假就正常启动 QQ
3. 安装器把 QQ 的启动方式改成带 `--no-sandbox`

### 为什么没成

**第一层：写不进去。**

```
touch: /Applications/QQ.app/Contents/Resources/app/package.json: Operation not permitted
```

`ls -l@` 看这个 app **没有 `restricted` 标志**，所以不是 SIP。真正原因是 **TCC · App Management**（系统设置 → 隐私与安全性 → App 管理）——它拦的是**发起写入的进程**，不是被写的文件。

所以：

- `sudo` 没用，root 一样被拦
- 但**从 Terminal 里执行就过得去**，因为 Terminal 已经被授予了这个权限

（这条本身是 `99-踩坑总表.md` 的 A1，记住它，以后会反复遇到。）

**第二层：即使写进去了，也白写。**

我用 Terminal + sudo 硬把 `main` 改成了绝对路径的 `loadNapCat.js`，还加了 `chflags uchg` 锁住。结果 QQ 启动后：

- `main` 又被改回 `./application.asar/app_launcher/index.js`
- 文件 mtime 是**启动那一刻**，说明是 QQ 自己写的
- 我在 `loadNapCat.js` 开头埋了一行 `console.log` 探针，写到 `/tmp` —— **探针从没出现过**，说明这个文件压根没被执行

也就是说：新版本 QQ 把真正的入口压进了 `application.asar`，改外面这个 `main` 字段它根本不看。安装器那套逻辑是给老版本 QQ 写的。

**第三层：没有自动更新可以背锅。**

我一度怀疑是 QQ 的自动更新把文件还原了。查完排除：

- `/Applications/QQ.app/Contents/Resources/QQUpdate.app` 不存在（这个版本没带）
- 装了文件监视器盯了 3 分钟，用户在安装器里点来点去，`package.json` 的 mtime **一次都没变**

结论：安装器压根没写过那个文件。界面上的「✅」是它自己的状态记录，不是实际状态。

### 结论

**放弃**。不是配置问题，是机制不匹配。

## 路二：Lagrange.OneBot

Lagrange 的好处是纯协议实现，不需要真 QQ 客户端，理论上跨平台最干净。

**它需要一个签名服务器**（处理 QQ 的登录握手），公共实例全挂了：

```
Signer server returned a NotFound
sign.lagrangecore.org → 404
```

自己搭签名服务要做协议逆向，超出「照着教程装」的范围。

### 结论

**放弃**。

---

## 路三：SnowLuma 跑在 Linux 容器里（可行）

关键洞察很简单：

> SnowLuma 官方不发 macOS 二进制，**但它发 Linux arm64 二进制**。而 macOS 上可以跑 Linux 虚拟机。

所以：

```
macOS
└── colima（轻量 Linux 虚拟机，底层 lima）
    └── Docker 容器（arm64）
        ├── Linux QQ（官方客户端，不是协议端）
        ├── SnowLuma（协议转换 → OneBot v11）
        └── noVNC（把容器里的桌面映射到 :6081）
```

**为什么这条路能行**：

- QQ 是**官方 Linux 客户端**，不是逆向协议，登录流程和正常一样（手机扫码确认）
- SnowLuma 在 Linux 上是原生支持，不用注入、不用改 asar
- noVNC 把容器里的界面映射出来，扫码这件事在浏览器里就能完成，不需要真的开一个 Linux 桌面
- 容器的网络直通宿主机端口，qq-bridge 连 `127.0.0.1:3000/3001` 就像连本机服务

**代价**：多一层虚拟机，第一次要下镜像（约 1–2 GB）；内存占用 +4 GB 左右。

**收益**：这条路能真正跑起来，而且掉线了重启容器就行，登录态在卷里。

## 一句话总结

| | 能不能用 | 卡在哪 |
|---|---|---|
| NapCat 安装器 | ❌ | TCC 写不进 + 新版 QQ 不看外部 `main` |
| Lagrange | ❌ | 签名服务器全挂 |
| **SnowLuma + colima** | ✅ | 只是重，不难 |
