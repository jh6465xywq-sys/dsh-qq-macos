# 09 · 运维：让它自己活着

跑通之后你不想每次开机都手动起三个东西。这一篇解决"重启之后还能用"。

有三个进程需要常驻：

```
colima 虚拟机  →  Docker 容器（snowluma）  →  qq-bridge  →  DSH
```

前两个 Docker 自己管（`--restart unless-stopped`），要操心的是后两个。

---

## 1. 守护进程

`scripts/watchdog.sh` 每 30 秒检查一次，挂了就拉起来：

```bash
#!/usr/bin/env bash
# 检查 bridge 活着没
if ! pgrep -f "qq-bridge/src/bridge.js" > /dev/null; then
  echo "[$(date)] bridge 挂了，重启" >> /tmp/watchdog.log
  cd ~/dafeiyu/qq-bridge
  nohup node src/bridge.js >> /tmp/qqbridge.out 2>&1 &
fi

# 检查容器
if [ "$(docker inspect -f '{{.State.Running}}' snowluma 2>/dev/null)" != "true" ]; then
  echo "[$(date)] 容器挂了，重启" >> /tmp/watchdog.log
  docker start snowluma
fi

# 检查 TTS（如果装了）
if ! curl -s -o /dev/null --max-time 3 http://127.0.0.1:9880/; then
  echo "[$(date)] TTS 挂了，重启" >> /tmp/watchdog.log
  # 你的 GPT-SoVITS 启动命令
fi
```

跑起来：

```bash
chmod +x scripts/watchdog.sh
nohup ./scripts/watchdog.sh > /tmp/watchdog.out 2>&1 &
```

**注意**：`nohup ... &` 挂在会结束的 shell 里会被带走。用 `launchd`（下面）更稳。

## 2. 开机自启（launchd）

macOS 的 launchd 比 cron 靠谱。建一个 plist：

```bash
cat > ~/Library/LaunchAgents/com.dafeiyu.qqbridge.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.dafeiyu.qqbridge</string>
  <key>ProgramArguments</key>
  <array>
    <string>/bin/bash</string>
    <string>/Users/<你>/dafeiyu/start-qq-bridge.sh</string>
  </array>
  <key>RunAtLoad</key>
  <true/>
  <key>KeepAlive</key>
  <true/>
  <key>StandardOutPath</key>
  <string>/tmp/qqbridge.out</string>
  <key>StandardErrorPath</key>
  <string>/tmp/qqbridge.err</string>
</dict>
</plist>
EOF

launchctl load ~/Library/LaunchAgents/com.dafeiyu.qqbridge.plist
```

`KeepAlive: true` = 挂了自动拉起，比 watchdog 更可靠。

卸载：

```bash
launchctl unload ~/Library/LaunchAgents/com.dafeiyu.qqbridge.plist
```

## 3. 那个每次重启都会变的端口

**DSH Desktop 的 Web API 端口 = GUI 端口，每次启动都随机。**

所以启动 bridge 之前要动态探测：

```bash
PORT=$(python3 ~/dafeiyu/find-dsh-port.py)
```

`scripts/find-dsh-port.py` 的原理是扫 `netstat` 里 DeepSeek 相关进程的 LISTEN 端口：

```python
import subprocess, re
out = subprocess.check_output(['/usr/sbin/netstat', '-anv', '-p', 'tcp'],
                              text=True, errors='ignore')
# 找到 DeepSeek 进程持有的监听端口
```

**两个坑**：

1. macOS 的 `netstat` 在 `/usr/sbin/` 下，PATH 里可能没有——要写绝对路径
2. 探测完要写进 `config.json` 的 `dsh.baseUrl` 再重启 bridge

## 4. 日志在哪

| 日志 | 路径 | 看什么 |
|---|---|---|
| bridge | `/tmp/qqbridge.out` | 消息收发、报错 |
| 容器 | `docker logs snowluma` | QQ 登录状态、OneBot |
| 控制台审计 | `~/dafeiyu/qq-bridge/state/bridge.log` | 每轮对话 |
| 工具调用 | `state/tool-calls.jsonl` | AI 调了哪些工具 |
| 守护进程 | `/tmp/watchdog.log` | 重启记录 |

**日常只需要看两个**：

```bash
tail -f /tmp/qqbridge.out                        # 有没有在干活
docker logs -f --tail 50 snowluma                # 登录掉没掉
```

## 5. 常见故障与恢复

### 掉线了（QQ 被踢）

```bash
# 重新扫码
open http://127.0.0.1:6081/vnc.html
```

登录态在卷里，重启容器不会丢；但被踢下线就必须重扫。

### 回了空白 / 一直不回

按顺序查：

```bash
docker logs snowluma --tail 30          # 消息进没进来
tail -30 /tmp/qqbridge.out              # bridge 收到没
curl -s http://127.0.0.1:<DSH端口>/     # DSH 活着没
```

再打开发送日志：

```bash
grep -E "发送失败|unauthorized|401" /tmp/qqbridge.out | tail -5
```

`401` → token 问题（踩坑 D1）；`session/model-unavailable` → provider id 写错（踩坑 D2）。

### 语音不出声 / 报超时

```bash
# TTS 服务活着吗
curl -s http://127.0.0.1:9880/ | head -c 100

# 参考音频还在吗
ls -la ~/dafeiyu/ref-denoised.wav
```

### 磁盘满了

GPT-SoVITS 的模型 + 容器镜像，轻松吃掉 10 GB：

```bash
docker system df            # 看容器占多少
docker image prune -a       # 清掉没用的镜像
```

## 6. 升级流程

**别在跑着的时候 pull。** 顺序：

```bash
# 1. 备份配置和角色卡
cp config.json config.json.bak
cp -r roles roles.bak

# 2. 停服务
launchctl unload ~/Library/LaunchAgents/com.dafeiyu.qqbridge.plist

# 3. 更新并重新打补丁
cd ~/dafeiyu/qq-bridge
git stash            # 保存本地改动
git pull
git stash pop        # 有冲突就手动解决
for p in ~/dsh-qq-macos/patches/0*.patch; do
  git apply --check "$p" && git apply "$p" || echo "冲突: $p"
done

# 4. 重启
launchctl load ~/Library/LaunchAgents/com.dafeiyu.qqbridge.plist
```

**升级前一定 `git stash`**，不然你的本地改动会被冲掉。

## 7. 安全检查清单

跑着之前过一遍：

- [ ] 小号，不是主号
- [ ] `config.json` 权限 `600`（`chmod 600 config.json`）
- [ ] 所有 key 在 `.env` 或 `config.json`，**不在 git 里**
- [ ] `allow.private` / `allow.groups` 是白名单，不是空（空=谁都不理）
- [ ] 控制台 token 不是默认值
- [ ] 容器端口只监听 `127.0.0.1`（不是 `0.0.0.0`）
