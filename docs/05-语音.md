# 05 · 语音：能听到 ta 说话

**这一篇是可选的，也是最重的一步。** 不装这块，机器人照样能用，只是只能打字。

两步：先让 ta 能发语音条（15 分钟），再让那个声音像某个人（25 分钟 + 4 GB）。

---

## 方案对比

| 方案 | 装起来 | 像不像 | 一句话耗时 | 适合 |
|---|---|---|---|---|
| macOS `say` | 0 分钟 | ❌ 机器味 | 0.5 秒 | 先跑通链路 |
| **GPT-SoVITS** | 25 分钟，4 GB | ✅ 很像 | 3–6 秒（CPU） | 长期用 |
| 豆包 / MiMo 云端 | 注册即可 | ✅ 很像 | 1–4 秒 | 不想装环境 |

建议：**先 `say` 把链路跑通**，确认能收到语音条了，再换 GPT-SoVITS。别一上来就装模型，装完发现链路不通会很崩溃。

---

# 第一步：让语音条能发出去

## 1.1 开开关

qq-bridge 的语音**默认是关的**。改 `config.json`：

```json
{
  "socialV2": {
    "voice": {
      "enabled": true,
      "sendVoice": true,
      "tts": {
        "engine": "say",
        "voice": "zh-CN-XiaoyiNeural"
      }
    }
  }
}
```

> ⚠️ **改完必须重启 MCP server**（不是重启 bridge）。MCP 工具是条件注册的——开关是 false 的时候 `qq_speak` 这个工具**压根不会出现**在 AI 的工具清单里。见 `99-踩坑总表.md` E1。

## 1.2 macOS 系统语音兜底

```bash
# 看有哪些中文音色
say -v '?' | grep zh_

# 试一句
say -v Tingting -o /tmp/test.aiff "今天想吃火锅，你陪我去嘛"

# 转成 QQ 要的格式
afconvert -f WAVE -d LEI16@24000 -c 1 /tmp/test.aiff /tmp/test.wav
```

macOS 自带 20 个中文音色（Tingting、Meijia、Sinji、Flo、Eddy…），够用来验证链路。

**缺点**：一听就是机器，而且念得慢。用 `rate` 参数可以调：

```bash
say -v Tingting -r 200 -o /tmp/test.aiff "别急，慢慢说"
```

# 第二步：克隆一个像的声音

## 2.1 装 GPT-SoVITS

```bash
cd ~/dafeiyu
git clone https://github.com/RVC-Boss/GPT-SoVITS.git
cd GPT-SoVITS

# 用 uv 装环境（比 pip 快 5 倍）
curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv --python 3.11
source .venv/bin/activate

# ⚠️ 关键：macOS 上不要装 CUDA 版
uv pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu
uv pip install -r requirements.txt
```

**Mac 上必装的几个补丁**（不装会一个个报错）：

```bash
uv pip install python-multipart matplotlib peft jieba_fast fast-langdetect
# 如果报 torchcodec / FFmpeg 相关，装 ffmpeg
brew install ffmpeg
```

## 2.2 准备参考音频

**这是全流程最影响效果的一步。**

| 素材 | 效果 |
|---|---|
| < 3 秒 | 飘，不像 |
| **6–8 秒，一句话说完整，无背景音** | **最稳** |
| > 10 秒 | 直接报错 |

**硬限制：3–10 秒**，超出会报：

```
Reference audio is outside the 3-10 second range, please choose another one!
```

处理素材：

```bash
# 裁到指定区间
ffmpeg -i input.m4a -ss 00:00:12 -t 7 -ar 32000 -ac 1 ref.wav

# 降噪（可选，但声音会更干净）
# 用 Python + noisereduce，prop_decrease 别开满，0.8 左右就够
```

⚠️ **降噪会让音频变慢**。7.8 秒的素材降噪后可能变 8.4 秒，别卡在 10 秒边缘。

## 2.3 起服务

```bash
cd GPT-SoVITS
.venv/bin/python api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS/configs/tts_infer.yaml
```

**要下模型**（约 2.5–3.5 GB），首次启动会挂很久。国内记得配镜像。

## 2.4 接进 qq-bridge

```json
{
  "socialV2": {
    "voice": {
      "tts": {
        "engine": "gptsovits",
        "apiBase": "http://127.0.0.1:9880",
        "refAudio": "/绝对路径/ref.wav",
        "promptText": "参考音频里说的那句话，一个字都不能错",
        "textLang": "zh",
        "promptLang": "zh"
      }
    }
  }
}
```

**`promptText` 必须和参考音频逐字一致。** 模型要靠它知道那段音频在说什么，写错就会大舌头。

怎么保证准确：用 Whisper 转写一遍。

```bash
# 在 GPT-SoVITS 的 venv 里
uv pip install faster-whisper
.venv/bin/python -c "
from faster_whisper import WhisperModel
m = WhisperModel('small', device='cpu', compute_type='int8')
segs, _ = m.transcribe('ref.wav', language='zh')
print(''.join(s.text for s in segs).strip())
"
```

把你手写的文字和转写结果**逐字对比**。实测手写版经常漏字。

## 2.5 台词长度的规律（重要）

模型有个坑：**台词太长会复读**。

实测数据（参考音频 4.39 秒）：

| 台词字数 | 结果 |
|---|---|
| 38 字 | 11.84 秒，复读 ❌ |
| 19 字 | 3.16 秒，正常 ✅ |

**经验规则：台词长度不要超过参考音频时长的 2 倍。**

- 参考 4 秒 → 台词别超过 8 秒（约 25 字）
- 参考 8 秒 → 台词别超过 16 秒（约 50 字）

发语音本来就该短。**控制在 20 字以内**，既自然又不会翻车。

## 2.6 控制频率：别让它刷语音

语音是"强表达"，发多了很烦。我用了三层约束：

**第一层：概率**（`config.json`）

```json
"strategy": {
  "enabled": true,
  "groupProbability": 0.15,
  "privateProbability": 0.3
}
```

bridge 每次唤醒会按会话类型注入一行提示：

> 【语音权重】本轮发语音的机会约 15%（群聊）……

**第二层：场景清单**（`patches/0005`，改的是 preset 提示词）

- **该发**：道晚安、早安、撒娇、哄人、对方要语音、语气比文字重要
- **不该发**：技术内容、报错、严肃话题、争吵、对方赶时间、群里刷屏
- **任何时候**：一轮最多一条，不连发，不替代正常回话

**第三层：硬上限**

```json
{ "maxPerMinute": 2, "maxPerHour": 10 }
```

超过直接拒绝，防止模型抽风。

三层配合下来：不会太频繁，但气氛对了会主动开口。

## 2.7 常见问题

**合成出来大舌头**
→ `promptText` 和音频对不上。用 Whisper 核对（2.4）。

**合成的语音只说一半 / 复读**
→ 台词太长。缩短到参考音频的 2 倍以内（2.5）。

**`spawn ffprobe ENOENT`**
→ `brew install ffmpeg`。或者用浏览器解码（见下面的附赠项目）。

**容器里报 `ENOENT` 找不到音频路径**
→ 容器看不到宿主机路径。**改用 base64 内联**，见 `99-踩坑总表.md` C3。

**CPU 合成太慢（6 秒+）**
→ 正常。想快只能上 GPU（Mac 没有 CUDA，M 系列的 MPS 支持不完整）。或者缩短台词。

## 附赠：声音实验室（给想自己玩的人）

`voice-lab/` 是一个独立的小网页，可以：

- 拖任意音频进去，自动转写
- 换文案、调语速和稳定度
- 存多个声音，随时切换

```bash
cd voice-lab
python3 voice-lab.py     # 打开 http://127.0.0.1:9881
```

它和 QQ 完全解耦，可以拿来试各种人的声音，调好参数再填进 `config.json`。

技术上有个巧思：**所有音频解码在前端用 Web Audio API 做**，转成 32k 单声道 WAV 再发后端。这样就不需要 ffmpeg，也绕开了 `ffprobe` 的问题。
