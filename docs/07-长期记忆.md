# 07 · 长期记忆：跨平台、会淡忘

> 前六篇讲的是"怎么把她接进 QQ"。这一篇讲的是**接进来之后，她凭什么记得昨天的事**。
>
> 这篇是本仓库唯一**不依赖 QQ** 的部分——换成抖音、微信、任何渠道，这套做法照样能用。
> 后面会说明：我们选的这一种不是唯一答案。

---

## 问题分三层，别混

| 层级 | 现象 | 归谁管 |
|---|---|---|
| 会话内 | 这一轮聊了 20 句，她知道第 1 句说了什么 | 上下文窗口 / 压缩 |
| 跨会话 | 昨晚聊的，今早新开一个会话还记不记得 | 会话存储 + 记忆注入 |
| **跨平台** | QQ 里说的，抖音那边知不知道 | **本篇** |

绝大多数"AI 没记性"的抱怨，其实是第二层。而真正让人觉得"她是我认识的那个人"的，是第三层——
**因为人是一个，不是一堆账号。**

---

## 核心一句话：按人存，不按账号存

这是整套东西里唯一要紧的设计决定。

每条记忆有两个字段：

```
key     = 哪个渠道的哪个号   "qq:<你的QQ号>" / "douyin:<sec_uid>"
person  = 这个人是谁          "owner"
```

- **写入**时同时带上 `key` 和 `person`
- **检索**时**按 `person` 查**，不按 `key`

于是：

```
QQ 里记下「下周三要体检」
      ↓  同一个 person
抖音里问「我下周要干嘛」
      ↓
查到，而且知道这句话是"在 QQ 说的"（每条带 channel 字段）
```

如果改成按 `key` 存，你就得写一堆"把 A 平台的 id 同步到 B 平台"的胶水代码，
而且每次加新平台都要改一遍。按人存，加平台只是多一个 `key` 前缀。

> 一个人在不同平台有不同 id，这件事必须由你的桥接层告诉他。
> 本仓库的做法是在调用接口时显式传 `person`，不猜、不做映射表。

---

## 一份库，所有渠道共用

```
~/.dafeiyu/memory/hub.json
```

**不分库**。分库的那一刻，你就有了"两份记忆慢慢不同步"的问题，而这类 bug 极难发现——
她会在 QQ 里记得，在抖音里忘掉，然后你以为是自己 prompt 写错了。

结构：

```json
{
  "version": 1,
  "entries": [
    {
      "id": "...",
      "key": "qq:<你的QQ号>",
      "person": "owner",
      "channel": "qq",
      "text": "下周三要体检，别吃太油",
      "vector": [0.013, -0.084, ...],
      "time": "2026-10-29T00:00:00.000Z",
      "source": "chat"
    }
  ]
}
```

`vector` 就是句子向量（本仓库用 `BAAI/bge-m3`，1024 维，硅基流动免费额度够个人用）。
检索时算余弦相似度，取 top-k。

**为什么不用关键词**：问「她还喜欢猫吗」和存的「养了只橘猫叫豆豆」没有任何共同词，
关键词检索必然漏。这不是优化问题，是能不能用的问题。

## 跨进程接口（换任何桥接都能接）

真正的桥接（qq-bridge、抖音插件、你自己写的）跟记忆库是两个进程。所以只暴露两个 HTTP 接口：

```
POST /api/memory/remember
  { "key": "qq:123", "person": "owner", "channel": "qq",
    "text": "下周三要体检", "source": "chat" }
  → { "ok": true, "id": "...", "duplicate": false }

POST /api/memory/recall
  { "key": "qq:123", "query": "我下周要干嘛", "topK": 5 }
  → { "ok": true, "hits": [ { "text": "...", "score": 0.717, "channel": "qq" } ] }
```

鉴权用 `~/.dafeiyu/memory/.key`（首次调用自动生成，`600` 权限），两边读同一个文件：

```
x-memory-key: <那个文件里的字符串>
```

**不要给每个渠道各配一份密钥**——那就是又回到"两套东西要对齐"的老路。

⚠️ 如果你的桥接有自己的控制台鉴权中间件，记得给 `/api/memory/*` 放行，
否则请求在到达路由前就被 `401` 拦掉了（我们踩过，报错是"未授权：请提供控制台访问令牌"，看起来像密钥错）。

## 提示词比代码重要（这条最容易被忽略）

我们第一版把工具全接好了，跑了一整天，记忆库一直是空的：

```
{"entries": []}
```

因为**提示词里只教了她一个会过期的轻量记忆工具**，而真正写进长期库的那个，一次都没提。

> 工具在那儿 ≠ 她会用。模型不会自己发现一个没被介绍过的工具。

提示词要明确三件事：

```
【记事儿】
- 什么时候记：对方亲口说的、以后还用得上的——住哪、养了什么、在忙什么、
  在意什么、讨厌什么、答应过的事、正在等的结果（考试/面试/体检/快递）
- 什么时候查：对方提到过去的事、或你想确认记不记得，先查一遍再开口，
  别瞎猜，也别把问过的事再问一遍
- 不记什么：临时的情绪、你自己猜的、一次性的闲聊
```

还有一条更狠的，效果最明显：

> **拿不准自己记不记得，先翻记录，别编。**

## 记忆衰减（拟人）：会忘才像人

一个什么都记得的 AI，反而不像人。真人会淡忘细节、记得情绪、把很多事压成一句话。

**目前这版实现的只是最朴素的一层**：按人设了条数上限（默认 400 条/key），超了淘汰最旧的。
这已经能防住"库越存越大、检索越来越慢"，但它不是拟人。

往上还能怎么做（都是可选项，本仓库没全做，写在这儿是给后来的人一个方向）：

1. **强度衰减**：每条记忆带一个 `strength`，随时间乘性衰减；被再次提起时强度回升。
   检索分数 = 相似度 × 强度。久没人提的事自然沉底——这最接近人的遗忘曲线。
2. **久不提降权**：不删，但权重降；偶尔还能翻出来，正好对应"一时想不起、过会儿突然想起来"。
3. **定期合并摘要**：一周前的零碎记忆合并成一句概括（"那阵子他在忙着弄机器人"），
   细节丢掉、轮廓留下。这是人压缩记忆的方式。
4. **情绪加权**：吵架、出事、特别开心的那次，权重给高一点。人会记住情绪强度大的事。

**为什么不在第一版全做**：每加一层都引入一堆参数，而参数是需要真实对话量去调的。
先跑通"记得住、查得到"，再谈"忘得像人"。顺序反了就是过早优化。

## 其他可选方案：这套不是唯一答案

**长期记忆的实现方法有很多种，本仓库选的只是其中一种，而且是我们顺手的那一种。**
如果你已经有别的基础设施，完全没必要照搬。

大致几类：

- **向量库 / 语义检索**（本仓库）
  优点：模糊提问也能命中。代价：要一个 embedding 服务，向量占空间。
- **文件型"伪无限记忆"**：把记忆写成一堆 Markdown，靠目录 + 索引 + 按需读取。
  Obsidian 那类外脑就是这种——本质是"不压缩上下文，而是让它可检索"。
  优点：**人能直接读、能编辑、能 git 版本化**，没有黑盒；适合本来就用笔记软件的人。
  代价：检索靠关键词和你自己的目录结构，写得乱就找不到；规模大起来要维护。
- **结构化数据库**（SQLite / Postgres）
  优点：精确查询、事务、能按字段过滤。代价：问"她喜欢猫吗"这种模糊问题不好使。
- **上下文压缩**（长对话自动摘要）
  优点：不用额外存储。代价：记的是"这段对话"，不是"这个人"，跨会话就断了。

**选择建议**：如果你已经在用 Obsidian / 笔记库，别为了这个再搭一套向量服务，
先把"按人存 + 按需检索"的思路套到你的文件结构上，往往就够了。
如果记忆条目会到几千上万，再考虑向量库。

> 换句话说：**这一篇讲的是"记忆该按人组织、该能被跨渠道查到"这个原则；
> 具体用什么存，是次要的工程选择。**

## 避坑清单

1. **别把 embedding 实现两遍。** 每个渠道各算一遍向量，等于两套模型、两套参数、
   两套结果，早晚不一致。统一调一个服务。
2. **失败不阻断。** 记忆服务挂了，聊天必须照常进行。所有调用都要 `catch` 掉，
   退化成"这次没记忆"，而不是"这次不回话"。
3. **隐私：整个库都是私事。** 谁住哪、在忙什么、要体检——这些比密钥还敏感。
   **不要提交、不要同步到任何云、不要打进日志。**
4. **去重。** 同一件事反复记会把库撑爆。写入时跟已有条目做相似度比较
   （我们用的阈值 0.96），近似就直接跳过。
5. **容量上限必设。** 没有上限的库，一年后检索会变慢、上下文会被稀释。

## 怎么确认真的通了

别只看代码，跑这三步：

```bash
# 1. 看库里有什么（应该是干净的，别再是空的了）
cat ~/.dafeiyu/memory/hub.json | python3 -c \
  "import json,sys; [print(e['channel'], e['person'], e['text']) for e in json.load(sys.stdin)['entries']]"

# 2. 在 A 平台说一件"以后用得上"的事

# 3. 在 B 平台问它
```

第 2 步之后库里应该多一行，第 3 步应该答得上来。
**如果第 2 步没多出行，问题在提示词，不在代码**——回去看"提示词比代码重要"那一节。

---

## 一句话总结

> 记忆的难点从来不是"怎么存"，而是**按人存、跨渠道查、并且让她知道该记**。
>
> 存法可以换（向量、文件、数据库），这三件事不能少。
