# 03 · 桥接：qq-bridge + DSH preset + MCP

底座跑起来之后，这一步把「QQ 消息」翻译成「DSH 会话」，并把能力开成 AI 能直接调的工具。

做完之后：你在 QQ 里发一句话，DSH 里的那个 agent 会收到，回的内容原路发回去。

---

## 1. 装 qq-bridge

```bash
cd ~/dafeiyu   # 或任何你放服务的地方
git clone https://github.com/Derpyu520/qq-bridge.git
cd qq-bridge
pnpm install --prod
```

**先记下版本**，后面打补丁要用：

```bash
git log --oneline -1
```

> 本仓库的补丁是基于 `a49877f`（2026-10 的版本）生成的。如果上游已经改了很多，`git apply` 会冲突——那就手动对着 patch 改，逻辑不复杂。

---

## 2. 打补丁

```bash
cd ~/dafeiyu/qq-bridge
for p in ~/dsh-qq-macos/patches/0*.patch; do
  echo "== $(basename $p)"
  git apply --check "$p" && git apply "$p" && echo "  ✅" || echo "  ⚠️ 冲突，需要手动改"
done
```

五个补丁分别加什么：

| 补丁 | 内容 | 必需？ |
|---|---|---|
| `0001-qzone-voice-strategy` | 空间说说 API、语音发送、语音权重注入 | 建议 |
| `0002-long-memory` | 长期记忆（语义检索） | 可选 |
| `0003-mcp-tools` | 把新能力开成 MCP 工具 | 跟 0001 配套 |
| `0004-safe-fetch-fakeip` | 放行 fake-ip 网段，修表情包 | 强烈建议 |
| `0005-preset-voice-rule` | 语音使用规则（进提示词） | 跟 0001 配套 |

装好依赖和补丁后确认能跑：

```bash
node --check src/bridge.js && echo "语法 OK"
```

## 3. 配 config.json

从模板复制，然后改这几处：

```bash
cp config.example.json config.json
```

```json
{
  "snowluma": {
    "httpBase": "http://127.0.0.1:3000",
    "wsUrl": "ws://127.0.0.1:3001",
    "accessToken": "<和 SnowLuma 里 HTTP/WS 设的同一个 token>"
  },
  "dsh": {
    "baseUrl": "http://127.0.0.1:<DSH 的端口>",
    "apiKey": "<你的 DSH token>"
  },
  "allow": {
    "private": [<你自己的大号 QQ 号>],
    "groups": []
  }
}
```

三个容易错的地方：

**① DSH 的端口每次重启都会变。** DSH Desktop 的 Web API 端口 = GUI 端口，每次启动随机。别写死：

```bash
# 用它自动探测
python3 ~/dafeiyu/find-dsh-port.py
```

（脚本见 `scripts/find-dsh-port.py`，原理是扫 `netstat` 里 DeepSeek 进程占的 LISTEN 端口。）

**② `allow.private` 必须填。** 空数组 = 谁都不理。这是白名单，不是"允许所有人"。

**③ token 从哪来。** SnowLuma 在 WebUI 的 OneBot 配置页里；DSH 的在 `~/.dsh/` 下的配置里（或者直接用控制台生成的）。

## 4. 装 DSH 这一侧

qq-bridge 自带一个安装脚本，负责三件事：装 preset、挂 MCP、注册 bundle。

```bash
node scripts/setup-dsh.mjs desktop
```

它做了什么（知道一下，出问题好排查）：

1. 把 `qq-chat` / `qq-chat-v2` 两个 preset 装到 `~/.dsh/`（DSH 0.1.7 起是 patch 层机制）
2. 在 `~/.dsh/profiles/desktop/cordis.patch.yml` 里加三条 MCP：

```yaml
- id: mcp-snowluma
  name: '@deepseek-ai/dsh-mcp-client'
  ...
- id: mcp-snowluma-host     # 只读探活，用来判断网关在不在
- id: mcp-web-search-safe   # 联网搜索（可选）
```

3. 在 profile 的 `package.json` 里注册 `qq-mode-console` 和 `qq-agent-presets` 两个 bundle

**装完必须重启 DSH**，否则 MCP 不生效。

## 5. 起 bridge

```bash
cd ~/dafeiyu/qq-bridge
nohup node src/bridge.js > /tmp/qqbridge.out 2>&1 &
```

或者用一键脚本（推荐，带环境变量和日志轮转）：

```bash
~/dsh-qq-macos/scripts/start-bridge.sh
```

看日志：

```bash
tail -f /tmp/qqbridge.out
```

**成功的样子**：

```
[WS] connected to ws://127.0.0.1:3001
[OneBot] session started: UIN=<小号>
[console] listening http://127.0.0.1:3100
```

---

## 6. 打开控制台

<http://127.0.0.1:3100>

**鉴权方式不是 `Authorization`**，是：

```
http://127.0.0.1:3100/?token=<state/console-token 里的值>
```

第一次打开如果提示令牌不对，先查这个文件：

```bash
cat ~/dafeiyu/qq-bridge/state/console-token
```

建议直接改成一个好记的（比如 `dafeiyu-qqbridge`），免得每次翻文件。

控制台里能干的：

- **人格与角色**：切角色卡、改模型、改思考强度
- **会话**：看每轮对话、手动唤醒
- **工具**：逐个开关
- **日志**：实时看

## 7. 第一次对话测试

用你的**大号**给小号发一条「在吗」。

预期：

1. `docker logs snowluma --tail 5` 出现消息上报
2. `/tmp/qqbridge.out` 出现 `BRIDGE_OK ... SENT N 段`
3. QQ 里收到回复

**没反应的话按这个顺序查**：

```bash
# ① SnowLuma 收到消息了吗
docker logs snowluma --tail 20 | grep -i message

# ② bridge 收到了吗
tail -20 /tmp/qqbridge.out | grep -i "wake\|BRIDGE"

# ③ DSH 侧回了吗
tail -30 ~/.dsh/logs/*.log 2>/dev/null | grep -i error

# ④ 发送失败了吗（401 就是 token 问题，见踩坑 D1）
grep -i "发送失败\|unauthorized" /tmp/qqbridge.out | tail -5
```

## 8. 这一步的验收标准

- [ ] `curl -H "Authorization: Bearer <token>" http://127.0.0.1:3000/get_login_info` 返回 ok
- [ ] `http://127.0.0.1:3100/?token=...` 能进控制台
- [ ] 大号发消息，小号能回

到这里，一个能聊天的机器人就活了。人格、表情包、语音在后面的文档里。
