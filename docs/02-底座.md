# 02 · 底座：容器 + SnowLuma + noVNC

目标：在 macOS 上跑起一个能登录 QQ 的 Linux 环境，并且你能在自己浏览器里看到 QQ 界面、扫码登录。

做完这一步，`http://127.0.0.1:5099` 是 SnowLuma 控制台，`http://127.0.0.1:6081/vnc.html` 是那个能看到 QQ 的"远程桌面"。

---

## 1. 装 colima

colima 是 macOS 上的轻量 Linux 虚拟机（底层是 lima + vz/qemu），比装完整 Docker Desktop 省一半内存。

```bash
brew install colima docker
```

没装 Homebrew 的话，也可以直接下二进制（本机就是这么干的）：

```bash
mkdir -p ~/bin/dafeiyu && cd ~/bin/dafeiyu
# lima / colima / docker CLI 三个二进制，下完 chmod +x，加进 PATH
```

验证：

```bash
colima version
docker version --format '{{.Client.Version}}'
```

---

## 2. 起虚拟机

```bash
colima start --cpu 4 --memory 8 --disk 40
```

参数怎么定：

| 参数 | 建议 | 说明 |
|---|---|---|
| `--cpu` | 4 | QQ + SnowLuma 都是常驻的，给少了登录会卡 |
| `--memory` | 8 | 少于 6 GB 容易 OOM |
| `--disk` | 40 | 镜像 + 数据，留够 |

**首次启动会下虚拟机镜像，国内大概率超时**（见 `99-踩坑总表.md` C1）。如果卡住：

```bash
colima start --cpu 4 --memory 8 --disk 40 --verbose
```

看它卡在哪个 URL，手动下好放进 lima 缓存目录，再重试。

---

## 3. 拉镜像

```bash
docker pull motricseven7/snowluma:latest
```

**Apple Silicon 注意**：这个镜像有 arm64 版本，会自动选对。用 `--platform linux/arm64` 强制指定也行。Intel Mac 用默认。

拉之前确认一下架构对不对：

```bash
docker manifest inspect motricseven7/snowluma:latest | grep -E "architecture|variant"
```

---

## 4. 起容器

```bash
docker run -d \
  --name snowluma \
  --restart unless-stopped \
  -p 3000:3000 \
  -p 3001:3001 \
  -p 5099:5099 \
  -p 6081:6081 \
  -e VNC_PASSWD='换成你自己的8位密码' \
  -e SNOWLUMA_SCREEN=1920x1080x24 \
  -e TZ=Asia/Shanghai \
  -e SNOWLUMA_QQ_FLAGS='' \
  -v snowluma-data:/app/data \
  -v snowluma-config:/app/.config \
  -v snowluma-local:/app/.local/share \
  motricseven7/snowluma:latest
```

**四个端口分别是**：

| 端口 | 用途 | 什么时候用 |
|---|---|---|
| `6081` | noVNC | 扫码登录、卡住时看 QQ 界面 |
| `5099` | SnowLuma WebUI | 配 OneBot、看日志 |
| `3000` | OneBot HTTP | qq-bridge 发消息走这里 |
| `3001` | OneBot WS | qq-bridge 收消息走这里 |

**卷一定要挂**，不然 `docker rm` 一次登录态就没了，得重新扫码。用命名卷（`snowluma-data`）比匿名卷好迁移。

**`SNOWLUMA_QQ_FLAGS`**：透传给 QQ 客户端的启动参数。默认留空。如果登录时报沙盒/显卡相关错误，可以试 `--no-sandbox`。

---

## 5. 扫码登录

打开 <http://127.0.0.1:6081/vnc.html>，输入你设的 `VNC_PASSWD`，应该能看到一个 Linux 桌面。

里面 QQ 已经在跑了。如果没在跑，容器内有启动脚本（`docker exec snowluma ls /app` 看）。

**手机上用 QQ 扫那个二维码**，然后按提示确认设备登录。

> ⚠️ 这里扫的是**小号**。非官方协议端，主号别用。

登录成功的标志（`docker logs snowluma`）：

```
[Hook] login detected: PID=86 UIN=<你的小号>
[OneBot] session started: UIN=<你的小号>
[OneBot.HTTP]  [http-default] listening 0.0.0.0:3000/
[OneBot.WS-Server] [ws-default] listening 0.0.0.0:3001/
```

看到这四行就对了。

---

## 6. 配 OneBot

打开 <http://127.0.0.1:5099>，用容器日志里打印的初始密码登录（`docker logs snowluma | grep -i "password\|admin"`）。

进去之后配 **OneBot v11**：

- 开启 **HTTP Server**，端口 `3000`
- 开启 **WS Server**（正向），端口 `3001`
- **两个都要设 accessToken，并且设成同一个值**

> 这是 `99-踩坑总表.md` D1 提到的坑。SnowLuma 会给 HTTP 和 WS 分别生成 token，而 qq-bridge 只有一个字段，不设成一样就必然 401。

**配置文件有两个，别改错**：

```
/app/data/config/onebot.json              ← 模板，改了不生效
/app/data/config/onebot_<你的QQ号>.json    ← 真正生效的
```

改完重启容器：

```bash
docker restart snowluma
```

验证（把 `<token>` 换成你的）：

```bash
# 不认证应该报 unauthorized
curl -s http://127.0.0.1:3000/get_login_info | head -c 120

# 认证后应该返回你的 QQ 信息
curl -s -H "Authorization: Bearer <token>" \
  http://127.0.0.1:3000/get_login_info
```

返回 `{"status":"ok","retcode":0,"data":{"user_id":<号码>,"nickname":"..."}}` 就通了。

## 7. 这一步的验收标准

三个都亮绿灯才往下走：

- [ ] `docker ps` 里 `snowluma` 是 `Up`
- [ ] `http://127.0.0.1:6081/vnc.html` 里 QQ 是登录状态
- [ ] `get_login_info` 带 token 返回 `retcode: 0`

## 常见问题

**Q：容器起来了但 VNC 是黑屏？**
QQ 可能崩了。`docker exec -it snowluma bash` 进去，`ps aux | grep qq` 看进程在不在，或者 `docker logs snowluma | tail -50`。

**Q：能登录但过几小时掉线？**
QQ 的风控。正常，重新扫一次。用`--restart unless-stopped` 让容器自己起来，登录态在卷里不会丢。

**Q：能不能不用容器，直接装 Linux QQ？**
Mac 版 QQ 是原生应用，没有 Linux 客户端。必须走 Linux。

**Q：Intel Mac 行吗？**
行，镜像有 x86_64 版本。colima 会自动用 qemu 跑，慢一些但能用。
